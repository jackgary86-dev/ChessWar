# Art assets

Everything under `assets/` is picked up by a glob in `src/ui/assets.ts`. **To change the art, replace the file with one of the same name; no code change is needed.** A file that is missing or fails to load falls back to the Unicode glyph (pieces) or is left out (icons), so the game always starts.

## Layout and names

| Folder    | Files                               | Notes                                                                                                  |
| --------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `pieces/` | `<P\|N\|B\|R\|Q>-<ivory\|ebony>.svg` | 10 sprites, 64 x 64 viewBox, transparent background, shared plinth baseline (see the style guide).      |
| `icons/`  | `<name>.svg`                        | HUD icons on a 24 px grid, 2 px round stroke, `currentColor`. Names in use: gold, xp, hp, reroll, lock, sell, sound-on, sound-off, settings. |
| `brand/`  | `logo-mark.svg`, `logo-wordmark.svg` | The mark is used on the start and handoff screens.                                                     |

Names are lowercase, hyphen-separated, one asset per file. Favicon and app icons live in `public/` (see `npm run icons`).

## Pipeline

- **Vite** bundles each SVG and fingerprints its url; small ones may be inlined.
- **Preload:** `src/ui/preload.ts` fetches every registered asset before play behind the loading screen (`#loading` in `index.html`), giving up after 5 s. Slow or failed art never blocks the game.
- **Budget:** all art together must stay under 2 MB on first load. `tests/assets.test.ts` fails if `assets/` grows past it.
- **Placeholders:** the piece SVGs are generated by `npm run pieces`, and `tests/sprites.test.ts` checks they match the generator. When an artist's files replace them, delete that generator check (and the script) in the same change.
